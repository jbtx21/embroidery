# Pinned runtime dependencies for headless Ink/Stitch (version and commit: see
# setup.sh, INKSTITCH_TAG / INKSTITCH_COMMIT). This is NOT Ink/Stitch's own
# requirements.txt -- it is the frozen `pip freeze` of a venv that has Ink/Stitch's
# actual runtime imports satisfied *without* wxPython (no Linux wheel on PyPI;
# run.py supplies wx_stub.py instead) and without its dev/test/type-checking extras
# (mypy, flake8, pytest, types-*, pywin32) -- those are irrelevant here, we
# only ever call `inkstitch.py --extension=... --format=...`, never the
# GUI or its test suite. `inkex` is the plain PyPI package (version 1.4.1,
# same version Ink/Stitch's own requirements.txt pins via
# EXTENSIONS_AT_INKSCAPE_1.4.1), not a git checkout.
#
# Held against Ink/Stitch v3.3.0 (30.09.2026; its requirements.txt and pyproject.toml at
# the tag): the same runtime set as the development version used before (pystitch,
# inkex 1.4.1, networkx, shapely, lxml, platformdirs, numpy==2.2.6, jinja2, tomli,
# colormath2, flask, fonttools, trimesh, diskcache). pyproject.toml also lists requests
# and flask-cors, but nothing in lib/ imports them. What `pip install -r requirements.txt`
# resolved on the day of the tag (31.07.2026, `uv pip compile --exclude-newer`; the release
# build installs it that way) and the pins below agree on the libraries that decide the
# stitches and the DST: numpy 2.2.6, shapely 2.1.2, networkx 3.6.1, lxml 5.4.0, pillow
# 12.3.0, pystitch 1.0.1. They differ in packages off that path: trimesh 5.1.0 against
# 4.12.2 (only contour fill calls it), fonttools 4.66.0 against 4.63.0 (lettering), and
# small ones (click, Werkzeug, cssselect, ...). The release build also installs PyGObject
# 3.50.0 for its GUI; here 3.58.0 is only imported.
#
# PyGObject and pycairo need system libraries at build time -- see
# inkstitch/setup.sh for the apt package list (libgirepository-2.0-dev,
# gobject-introspection, libcairo2-dev, pkg-config, python3-dev or the
# matching pythonX.Y-dev).
